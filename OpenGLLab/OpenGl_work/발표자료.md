## 📌 6. 핵심 기술 ① - 스카이박스를 활용한 배경 구현

### 슬라이드 6-1: 스카이박스란?

```
🌌 스카이박스 (Skybox)
- 3D 공간을 감싸는 배경 이미지
- 6면의 큐브맵(Cubemap) 사용
- 카메라가 어디를 보든 배경이 보임

┌─────────────────────────────────────┐
│  [Top]                               │
│  [Left] [Front] [Right] [Back]       │
│  [Bottom]                            │
└─────────────────────────────────────┘

특징:
- 항상 카메라 뒤에서 렌더링 (깊이 테스트 우회)
- HDR 이미지 지원 (고품질 조명)
- 무한히 멀리 있는 배경 효과
```

### 슬라이드 6-2: 구현 방법

```
1. 큐브 정점 데이터 생성
   - 6면의 정점 좌표 정의
   - VAO, VBO에 업로드

2. HDR 이미지 로드
   - assets/skybox/ 폴더의 6개 HDR 파일
   - GL_TEXTURE_CUBE_MAP에 바인딩

3. 셰이더 처리
   - Vertex Shader: 큐브 정점을 그대로 출력
   - Fragment Shader: 큐브맵 샘플링
   - glDepthFunc(GL_LEQUAL) 사용 (항상 배경으로)

4. 렌더링 순서
   - 메인 씬 렌더링 후
   - 깊이 테스트 변경
   - 스카이박스 렌더링
```

### 슬라이드 6-3: 코드 예시

```cpp
// 큐브맵 로드
std::vector<std::string> faces = {
    "assets/skybox/right.hdr",
    "assets/skybox/left.hdr",
    "assets/skybox/top.hdr",
    "assets/skybox/bottom.hdr",
    "assets/skybox/front.hdr",
    "assets/skybox/back.hdr"
};
unsigned int cubemap = loadCubemap(faces);

// 렌더링
glDepthFunc(GL_LEQUAL);  // 깊이 테스트 변경
skyboxShader.use();
glBindTexture(GL_TEXTURE_CUBE_MAP, cubemap);
glDrawArrays(GL_TRIANGLES, 0, 36);
glDepthFunc(GL_LESS);  // 원래대로 복원
```

## 📌 7. 핵심 기술 ② - 스켈레탈 애니메이션 기능 구현 ⭐중요⭐

### 슬라이드 7-1: 스켈레탈 애니메이션이란?

```
🦴 스켈레탈 애니메이션 = 뼈대를 움직여서 캐릭터 애니메이션

[일반 애니메이션]
- 모든 정점을 직접 움직임 → 데이터 많음

[스켈레탈 애니메이션]
- 뼈대(Bone)만 움직임
- 정점은 뼈대를 따라 자동으로 변형
- 적은 데이터로 부드러운 애니메이션 가능

         🦴 Spine(척추)
             │
    ┌────────┼────────┐
    🦴       🦴       🦴
   LeftArm  Head   RightArm
```

### 슬라이드 7-2: 뼈대 가중치 (Bone Weight)

```
한 정점이 여러 뼈대의 영향을 받음 (최대 4개)

예: 팔꿈치 부근 정점
┌─────────────────────────────────────┐
│  Bone ID  │  Weight (영향력)         │
├───────────┼─────────────────────────┤
│  UpperArm │    0.6 (60%)            │
│  LowerArm │    0.4 (40%)            │
│  -1       │    0.0                  │
│  -1       │    0.0                  │
└───────────┴─────────────────────────┘

최종 위치 = (UpperArm 변환 × 0.6) + (LowerArm 변환 × 0.4)
```

### 슬라이드 7-3: 애니메이션 재생 과정

```
1. Animation 클래스
   - FBX에서 키프레임 데이터 로드
   - 각 뼈대별 [시간 → 변환] 정보 저장

2. Animator 클래스
   - 매 프레임 시간 업데이트
   - 뼈대 계층 구조 순회 (부모 → 자식)
   - 최종 변환 행렬 100개 계산

3. Shader로 전달
   - finalBonesMatrices[100] uniform
   - GPU에서 정점 변환 수행
```

### 슬라이드 7-4: 셰이더 코드 (Vertex Shader)

```glsl
// 뼈대 변환 계산
mat4 boneTransform = mat4(0.0);
boneTransform += finalBonesMatrices[BoneID[0]] * Weight[0];
boneTransform += finalBonesMatrices[BoneID[1]] * Weight[1];
boneTransform += finalBonesMatrices[BoneID[2]] * Weight[2];
boneTransform += finalBonesMatrices[BoneID[3]] * Weight[3];

// 정점에 적용
vec4 localPos = boneTransform * vec4(aPos, 1.0);
gl_Position = projection * view * model * localPos;
```

### 슬라이드 7-5: 구현 클래스 구조

```
Model (모델 로딩)
  └─ ExtractBoneWeightForVertices()
     └─ 각 정점에 뼈대 ID와 가중치 저장

Animation (애니메이션 데이터)
  └─ FBX에서 키프레임 로드
  └─ Bone 클래스로 각 뼈대의 변환 저장

Animator (애니메이션 재생)
  └─ UpdateAnimation(dt) - 시간 진행
  └─ CalculateBoneTransform() - 재귀적으로 뼈대 변환 계산
  └─ GetFinalBoneMatrices() - 셰이더에 전달할 행렬 반환

CharacterBase (캐릭터 관리)
  └─ 여러 애니메이션 등록 ("idle", "attack" 등)
  └─ PlayAnimation(key) - 애니메이션 전환
  └─ Render() - 뼈대 행렬을 셰이더에 전달 후 그리기
```

## 📌 8. 핵심 기술 ③ - 간단한 턴제 시스템 구현

### 슬라이드 8-1: 턴제 시스템 개요

```
🎮 턴제 전투 시스템
- 플레이어가 액션을 선택하면 실행
- 액션이 끝나면 적이 반응
- 순차적으로 턴이 진행됨

┌─────────────────────────────────────┐
│  [Player Turn]                      │
│  → Attack / Slash / Cast 선택       │
│  → 애니메이션 재생                   │
│  → Enemy에게 데미지                 │
│  → 액션 종료                        │
├─────────────────────────────────────┤
│  [Enemy Turn]                       │
│  → Stun 상태 (피격 반응)            │
│  → Punch 반격                       │
│  → Player에게 데미지                │
│  → 턴 종료                          │
└─────────────────────────────────────┘
```

### 슬라이드 8-2: 상태 전이도

```
[Player 상태]
┌──────────────────────────────────────┐
│  idle ←→ attack ←→ idle             │
│       ←→ slash  ←→                  │
│       ←→ cast   ←→                  │
└──────────────────────────────────────┘

[Enemy 상태]
┌──────────────────────────────────────┐
│  idle → (피격) → stun → punch → idle │
│       → (HP=0) → dying → [종료]      │
└──────────────────────────────────────┘
```

### 슬라이드 8-3: 구현 방식

```cpp
// Player 클래스
struct Action {
    std::string key;       // 애니메이션 키
    int damage = 10;       // 데미지 양
    float duration = 1.0f; // 지속 시간
    float timer = 0.0f;    // 현재 경과 시간
    bool playing = false;  // 재생 중인지
};

void UpdateActions(float dt) {
    // 액션 타이머 업데이트
    if (attack_.playing) {
        attack_.timer += dt;
        if (attack_.timer >= attack_.duration) {
            PlayAnimation("idle");  // 액션 종료
            attack_.playing = false;
            onActionFinished_();  // 콜백 호출 (적 스턴 트리거)
        }
    }
}

bool StartAttack() {
    if (attack_.playing) return false;
    PlayAnimation("attack");
    attackTarget_->TakeDamage(10, "Player attack");
    attack_.playing = true;
    attack_.timer = 0.0f;
    return true;
}
```

### 슬라이드 8-4: 콜백 시스템

```cpp
// Player의 액션이 끝나면 Enemy가 반응
player.SetOnActionFinished([&enemy]() {
    enemy.TriggerStunSequence();  // 적이 스턴 상태로 전환
});

// Enemy의 스턴이 끝나면 자동으로 반격
void Enemy::UpdateActions(float dt) {
    if (stun_.playing) {
        stun_.timer += dt;
        if (stun_.timer >= stun_.duration) {
            StartPunch();  // 자동으로 펀치 시작
        }
    }
}
```

### 슬라이드 8-5: HP 시스템

```cpp
// CharacterStatus 구조체
struct CharacterStatus {
    std::string name;
    int hp = 100;
};

// 데미지 처리
void Enemy::TakeDamage(int amount, const char* source) {
    status_.hp = std::max(0, status_.hp - amount);
    
    // HP가 0이 되면 사망
    if (status_.hp == 0 && !dying_.playing) {
        StartDying();  // 사망 애니메이션 시작
    }
}
```

## 📌 9. 추가 기술 - 그림자 (Shadow Mapping)

### 슬라이드 9-1: Shadow Mapping 원리

```
2-Pass 렌더링 기법

[Pass 1: 깊이 맵 생성]
- 광원 위치에서 장면을 봄
- 색상 대신 깊이(거리)만 저장
- 결과: Depth Map (그림자 판정용)

[Pass 2: 실제 렌더링]
- 카메라 위치에서 렌더링
- 각 픽셀에서 광원까지 거리 계산
- Depth Map과 비교 → 그림자 여부 판정
```

### 슬라이드 9-2: PCF (부드러운 그림자)

```
문제: 기본 Shadow Map은 계단 현상 발생

해결: PCF (Percentage Closer Filtering)
- 주변 픽셀도 함께 샘플링
- 평균값으로 부드러운 그림자 생성

┌─────────────────────────────┐
│  [기본]      →    [PCF]     │
│  ████████        ▓▓██████   │
│  ████████   →    ▒▓██████   │
│  딱딱함          부드러움     │
└─────────────────────────────┘
```

## 📌 10. 추가 기술 - 조명 (Blinn-Phong)

```
Blinn-Phong 조명 모델

최종 색상 = Ambient + Diffuse + Specular

┌───────────────────────────────────────────┐
│ Ambient (환경광)                           │
│ - 전체적으로 균일한 밝기                     │
│ - 완전히 어두운 부분 방지                    │
├───────────────────────────────────────────┤
│ Diffuse (난반사)                           │
│ - 빛이 표면에서 퍼지는 효과                  │
│ - 법선과 광원 방향의 내적으로 계산            │
├───────────────────────────────────────────┤
│ Specular (정반사)                          │
│ - 반짝이는 하이라이트                       │
│ - Half-vector 방식 사용                    │
└───────────────────────────────────────────┘
```
