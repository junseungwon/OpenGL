## 1. 스켈레탈 애니메이션이란?

### 🎯 기본 개념

**스켈레탈 애니메이션**은 실제 사람의 뼈대처럼, 3D 모델 내부에 **뼈대(Bone)**를 넣고 뼈대를 움직여서 캐릭터를 애니메이션화하는 방식입니다.

```
일반 애니메이션 (Vertex Animation)
- 모든 정점을 직접 움직임
- 예: 0초에 정점 A가 (1,2,3), 1초에 (2,3,4)
- 문제: 데이터가 엄청 많음, 부드럽지 않음

스켈레탈 애니메이션 (Skeletal Animation)
- 뼈대만 움직임
- 정점은 뼈대를 따라 자동으로 변형
- 예: 팔 뼈대를 90도 회전 → 팔 주변 정점들이 자동으로 따라감
- 장점: 데이터 적음, 부드러움, 자연스러움
```

### 🦴 뼈대 구조 예시

```
캐릭터의 뼈대 계층 구조:

Root (루트)
  ├─ Spine (척추)
  │   ├─ Chest (가슴)
  │   │   ├─ LeftShoulder (왼쪽 어깨)
  │   │   │   ├─ LeftUpperArm (왼쪽 상완)
  │   │   │   │   └─ LeftLowerArm (왼쪽 하완)
  │   │   │   │       └─ LeftHand (왼손)
  │   │   │   └─ RightShoulder (오른쪽 어깨)
  │   │   │       └─ ... (같은 구조)
  │   │   └─ Head (머리)
  │   └─ Hip (엉덩이)
  │       ├─ LeftUpperLeg (왼쪽 대퇴)
  │       │   └─ LeftLowerLeg (왼쪽 종아리)
  │       │       └─ LeftFoot (왼발)
  │       └─ RightUpperLeg (오른쪽 대퇴)
  │           └─ ... (같은 구조)
```

**중요한 점**: 부모 뼈대가 움직이면 자식 뼈대도 **자동으로 따라 움직입니다**.
- 예: 어깨를 올리면 → 팔 전체가 올라감
- 예: 척추를 앞으로 구부리면 → 상체 전체가 앞으로 구부러짐

## 2. 뼈대 가중치 (Bone Weight) 상세 설명

### 🎯 왜 가중치가 필요한가?

**한 정점이 여러 뼈대의 영향을 받아야 자연스러운 애니메이션이 됩니다.**

예를 들어, **팔꿈치 부근의 정점**을 생각해봅시다:

```
팔꿈치 정점의 위치:
┌─────────────────────────────────────┐
│  이 정점은 어디에 있나?              │
│  - 상완(UpperArm) 뼈대의 끝부분      │
│  - 하완(LowerArm) 뼈대의 시작 부분   │
│                                     │
│  → 두 뼈대 모두의 영향을 받음!        │
└─────────────────────────────────────┘
```

### 📊 가중치 데이터 구조

코드에서 정점은 다음과 같이 저장됩니다:

```cpp
// mesh.h의 Vertex 구조체
struct Vertex {
    glm::vec3 Position;     // 위치
    glm::vec3 Normal;       // 법선
    glm::vec2 TexCoords;    // 텍스처 좌표
    
    // 🎯 뼈대 가중치 데이터
    // ⚠️ 중요: 이 정점이 어떤 뼈대의 영향을 받는지를 저장
    // 방향: 뼈대 → 정점 (뼈대가 정점을 움직임)
    int m_BoneIDs[4];       // 이 정점이 영향을 받는 뼈대 ID들 (최대 4개)
    float m_Weights[4];     // 각 뼈대가 이 정점에 미치는 영향력 (0.0 ~ 1.0)
};
```

**예시: 팔꿈치 정점**

이 정점은 **두 뼈대의 영향을 받습니다**:
- UpperArm 뼈대(ID=5)의 60% 영향
- LowerArm 뼈대(ID=6)의 40% 영향

```
m_BoneIDs[0] = 5   // 이 정점이 영향을 받는 뼈대: UpperArm
m_Weights[0] = 0.6 // UpperArm이 이 정점에 미치는 영향력: 60%

m_BoneIDs[1] = 6   // 이 정점이 영향을 받는 뼈대: LowerArm
m_Weights[1] = 0.4 // LowerArm이 이 정점에 미치는 영향력: 40%

m_BoneIDs[2] = -1  // 사용 안 함 (뼈대 없음)
m_Weights[2] = 0.0

m_BoneIDs[3] = -1  // 사용 안 함 (뼈대 없음)
m_Weights[3] = 0.0

총합: 0.6 + 0.4 = 1.0 (정상)
```

**의미:**
- UpperArm 뼈대가 움직이면 → 이 정점이 60%만큼 따라 움직임
- LowerArm 뼈대가 움직이면 → 이 정점이 40%만큼 따라 움직임
- 두 뼈대가 동시에 움직이면 → 두 영향의 합으로 움직임

### 🔍 가중치가 어떻게 결정되는가?

**FBX 파일에 이미 포함되어 있습니다!**

```cpp
// model.h의 ExtractBoneWeightForVertices() 함수
void Model::ExtractBoneWeightForVertices(vector<Vertex>& vertices, aiMesh* mesh, const aiScene* scene)
{
    // FBX 파일에서 각 뼈대의 정보를 읽어옴
    for (unsigned int boneIndex = 0; boneIndex < mesh->mNumBones; ++boneIndex)
    {
        string boneName = mesh->mBones[boneIndex]->mName.C_Str();
        
        // ⚠️ 중요: 각 뼈대가 어떤 정점에 얼마나 영향을 주는지
        // 방향: 뼈대 → 정점 (뼈대가 정점을 움직임)
        auto weights = mesh->mBones[boneIndex]->mWeights;
        int numWeights = mesh->mBones[boneIndex]->mNumWeights;
        
        for (int weightIndex = 0; weightIndex < numWeights; ++weightIndex)
        {
            int vertexId = weights[weightIndex].mVertexId;  // 정점 번호
            float weight = weights[weightIndex].mWeight;    // 이 뼈대가 이 정점에 미치는 영향력 (0~1)
            
            // 정점에 뼈대 정보 추가
            // "이 정점은 이 뼈대의 영향을 받는다"고 기록
            SetVertexBoneData(vertices[vertexId], boneID, weight);
        }
    }
}
```

**3D 모델링 프로그램(Blender, Maya 등)에서 애니메이터가 직접 설정합니다:**
- 팔꿈치 부근 정점 → 상완 뼈대 60% 영향, 하완 뼈대 40% 영향
- 어깨 부근 정점 → 어깨 뼈대 80% 영향, 가슴 뼈대 20% 영향
- 등등...

**요약:**
- `m_BoneIDs[4]`: **이 정점이 영향을 받는** 뼈대 ID들
- `m_Weights[4]`: **각 뼈대가 이 정점에 미치는** 영향력
- 방향: **뼈대 → 정점** (뼈대가 정점을 움직임)

### 🧮 가중치 계산 예시

**팔꿈치 정점이 두 뼈대의 영향을 받을 때:**

```
상황: 상완 뼈대가 30도 회전, 하완 뼈대는 그대로

1. 상완 뼈대의 변환 행렬: M_upper
2. 하완 뼈대의 변환 행렬: M_lower

3. 최종 변환 행렬 계산:
   M_final = (M_upper × 0.6) + (M_lower × 0.4)
   
   ⚠️ 주의: 실제로는 행렬을 더하는 게 아니라
   각각 변환한 결과를 가중 평균합니다.
   
   실제 계산:
   - 상완으로 변환: pos1 = M_upper × 원래위치
   - 하완으로 변환: pos2 = M_lower × 원래위치
   - 최종 위치: pos_final = pos1 × 0.6 + pos2 × 0.4
```

## 3. 애니메이션 재생 과정 (전체 흐름)

### 📋 전체 흐름도

```
[게임 시작]
    │
    ▼
1. 모델 로드 (Model 클래스)
   └─ FBX 파일 읽기
   └─ 정점, 뼈대 정보 추출
   └─ 각 정점에 뼈대 ID와 가중치 저장
    │
    ▼
2. 애니메이션 로드 (Animation 클래스)
   └─ FBX 파일에서 키프레임 데이터 읽기
   └─ 각 뼈대별 키프레임 저장
   └─ 뼈대 계층 구조 저장
    │
    ▼
3. Animator 생성
   └─ Animation과 연결
   └─ 최종 변환 행렬 배열 초기화 (100개)
    │
    ▼
[매 프레임마다 반복]
    │
    ▼
4. UpdateAnimation(deltaTime) 호출
   │
   ├─ 4-1. 시간 업데이트
   │   └─ m_CurrentTime += TicksPerSecond * deltaTime
   │   └─ 애니메이션 길이로 나머지 연산 (루프)
   │
   ├─ 4-2. 뼈대 변환 계산 시작
   │   └─ CalculateBoneTransform(루트 노드) 호출
   │
   └─ 4-3. 재귀적으로 모든 뼈대 처리
       │
       ├─ 각 뼈대마다:
       │   ├─ Bone::Update(현재시간) 호출
       │   │   ├─ 키프레임 사이에서 보간
       │   │   ├─ 위치 보간 (선형)
       │   │   ├─ 회전 보간 (SLERP)
       │   │   ├─ 크기 보간 (선형)
       │   │   └─ 최종 변환 행렬 계산
       │   │
       │   ├─ 부모 변환 × 로컬 변환 = 글로벌 변환
       │   │
       │   └─ 글로벌 변환 × 오프셋 = 최종 행렬
       │       └─ m_FinalBoneMatrices[뼈대ID]에 저장
       │
       └─ 자식 뼈대들도 재귀적으로 처리
    │
    ▼
5. 셰이더에 행렬 전달
   └─ for (int i = 0; i < 100; i++)
       shader.setMat4("finalBonesMatrices[" + i + "]", m_FinalBoneMatrices[i])
    │
    ▼
6. GPU에서 정점 변환
   └─ 각 정점마다 뼈대 가중치로 변환 행렬 계산
   └─ 정점 위치 변환
    │
    ▼
7. 화면에 그리기
```

**UpdateAnimation() 내부:**

```cpp
// animator.cpp
void Animator::UpdateAnimation(float dt)
{
    // 4-1. 시간 업데이트
    m_CurrentTime += m_CurrentAnimation->GetTicksPerSecond() * dt;
    // 예: TicksPerSecond = 30, dt = 0.016초
    //     → m_CurrentTime += 30 * 0.016 = 0.48 틱 증가
    
    // 애니메이션이 끝나면 처음부터 다시 (루프)
    m_CurrentTime = fmod(m_CurrentTime, m_CurrentAnimation->GetDuration());
    
    // 4-2. 뼈대 변환 계산 시작
    // 루트 노드부터 시작, 부모 변환은 단위 행렬
    CalculateBoneTransform(&m_CurrentAnimation->GetRootNode(), glm::mat4(1.0f));
}
```

**CalculateBoneTransform() - 재귀 함수:**

이 함수가 **부모-자식 관계의 핵심**입니다!

```cpp
// animator.cpp
void Animator::CalculateBoneTransform(const AssimpNodeData* node, glm::mat4 parentTransform)
{
    std::string nodeName = node->name;  // 예: "UpperArm"
    glm::mat4 nodeTransform = node->transformation;  // 기본 변환
    
    // 4-3-1. 이 노드가 애니메이션되는 뼈대인가?
    Bone* bone = m_CurrentAnimation->FindBone(nodeName);
    if (bone) {
        // 4-3-2. 현재 시간에 맞는 변환 계산
        bone->Update(m_CurrentTime);
        // → 키프레임 사이에서 보간하여 변환 행렬 계산
        
        nodeTransform = bone->GetLocalTransform();
        // 예: 현재 시간이 0.5초면, 0초와 1초 키프레임 사이에서 보간
        //     → 회전 45도 (0도와 90도의 중간)
    }
    
    // 4-3-3. ⭐ 핵심: 글로벌 변환 계산
    // 부모 변환 × 로컬 변환 = 이 뼈대의 글로벌 변환
    glm::mat4 globalTransformation = parentTransform * nodeTransform;
    
    // 🎯 부모-자식 관계 예시:
    // 예시 1: 어깨(부모)가 30도 회전, 팔(자식)이 45도 회전
    //   → 팔의 최종 회전 = 30도(부모) + 45도(자식) = 75도
    //
    // 예시 2: 어깨(부모)가 (0, 1, 0)만큼 위로 이동, 팔(자식)이 (1, 0, 0)만큼 오른쪽 이동
    //   → 팔의 최종 위치 = (0, 1, 0) + (1, 0, 0) = (1, 1, 0)
    //   → 팔도 위로 올라가고, 오른쪽으로도 이동함!
    
    // 4-3-4. 이 뼈대가 정점에 영향을 주는 뼈대인가?
    auto boneInfoMap = m_CurrentAnimation->GetBoneIDMap();
    if (boneInfoMap.find(nodeName) != boneInfoMap.end()) {
        int index = boneInfoMap[nodeName].id;  // 뼈대 ID (예: 5)
        
        // 4-3-5. 최종 변환 행렬 계산
        glm::mat4 offset = boneInfoMap[nodeName].offset;  // 오프셋 행렬
        m_FinalBoneMatrices[index] = globalTransformation * offset;
        // 오프셋 행렬: 정점을 뼈대의 로컬 공간으로 변환
        // 최종 행렬: 뼈대 변환을 정점에 적용할 수 있게 만든 행렬
    }
    
    // 4-3-6. ⭐ 핵심: 자식 뼈대들도 재귀적으로 처리
    for (int i = 0; i < node->childrenCount; i++)
        CalculateBoneTransform(&node->children[i], globalTransformation);
    // 🎯 중요: 자식에게는 이 뼈대의 글로벌 변환을 부모 변환으로 전달!
    // → 자식은 부모의 변환을 그대로 상속받음
}
```

### 🎯 부모-자식 관계 상세 설명

**핵심 원리:**
```
부모 뼈대가 1만큼 움직이면 → 자식 뼈대도 1만큼 움직임
자식 뼈대가 추가로 0.5만큼 움직이면 → 자식의 최종 위치 = 1 + 0.5 = 1.5
```

**실제 예시:**

```
뼈대 계층 구조:
Shoulder (어깨) - 부모
  └─ UpperArm (상완) - 자식
      └─ LowerArm (하완) - 손자

시나리오 1: 어깨만 위로 1만큼 올림
- 어깨: (0, 1, 0) 이동
- 상완: 부모 따라 (0, 1, 0) 이동
- 하완: 부모 따라 (0, 1, 0) 이동
→ 전체 팔이 위로 올라감!

시나리오 2: 어깨 위로 1, 상완 추가로 0.5 앞으로
- 어깨: (0, 1, 0) 이동
- 상완: (0, 1, 0) + (0, 0, 0.5) = (0, 1, 0.5) 이동
- 하완: 상완 따라 (0, 1, 0.5) 이동
→ 팔이 위로 올라가고 앞으로도 나옴!

시나리오 3: 어깨 위로 1, 상완 30도 회전, 하완 추가로 45도 회전
- 어깨: (0, 1, 0) 이동
- 상완: (0, 1, 0) 이동 + 30도 회전
- 하완: (0, 1, 0) 이동 + 30도 회전(상완) + 45도 회전(자신) = 75도 회전
→ 전체 팔이 위로 올라가고, 하완은 총 75도 회전!
```

**코드에서의 구현:**

```cpp
// 1단계: 어깨(부모) 처리
glm::mat4 shoulderGlobal = parentTransform * shoulderLocal;
// parentTransform = 단위 행렬 (루트)
// shoulderLocal = (0, 1, 0) 이동
// → shoulderGlobal = (0, 1, 0) 이동

// 2단계: 상완(자식) 처리
glm::mat4 upperArmGlobal = shoulderGlobal * upperArmLocal;
// shoulderGlobal = (0, 1, 0) 이동 (부모의 변환!)
// upperArmLocal = 30도 회전
// → upperArmGlobal = (0, 1, 0) 이동 + 30도 회전

// 3단계: 하완(손자) 처리
glm::mat4 lowerArmGlobal = upperArmGlobal * lowerArmLocal;
// upperArmGlobal = (0, 1, 0) 이동 + 30도 회전 (부모의 변환!)
// lowerArmLocal = 45도 회전
// → lowerArmGlobal = (0, 1, 0) 이동 + 30도 회전 + 45도 회전
```

**요약:**
- 부모가 움직이면 → 자식도 **자동으로** 따라 움직임
- 자식이 추가로 움직이면 → 부모 변환 + 자식 변환 = 최종 변환
- 이것이 **계층 구조(Hierarchy)**의 핵심!

**Bone::Update() - 키프레임 보간:**

```cpp
// bone.cpp
void Bone::Update(float animationTime)
{
    // 현재 시간에 맞는 위치, 회전, 크기를 보간
    glm::mat4 translation = InterpolatePosition(animationTime);
    glm::mat4 rotation = InterpolateRotation(animationTime);
    glm::mat4 scale = InterpolateScaling(animationTime);
    
    // 최종 변환 행렬 = 이동 × 회전 × 크기
    m_LocalTransform = translation * rotation * scale;
}
```

**InterpolateRotation() 예시:**

```cpp
// bone.cpp
glm::mat4 Bone::InterpolateRotation(float animationTime)
{
    // 예: 현재 시간이 0.5초
    // 키프레임: 0초에 회전 0도, 1초에 회전 90도
    
    // 1. 현재 시간이 어느 키프레임 사이에 있는지 찾기
    int p0Index = GetRotationIndex(animationTime);  // 0번 키프레임
    int p1Index = p0Index + 1;                      // 1번 키프레임
    
    // 2. 보간 비율 계산 (0.0 ~ 1.0)
    float scaleFactor = GetScaleFactor(
        m_Rotations[p0Index].timeStamp,  // 0.0
        m_Rotations[p1Index].timeStamp,  // 1.0
        animationTime                     // 0.5
    );
    // scaleFactor = (0.5 - 0.0) / (1.0 - 0.0) = 0.5
    
    // 3. 구면 선형 보간 (SLERP) - 회전은 쿼터니언으로
    glm::quat finalRotation = glm::slerp(
        m_Rotations[p0Index].orientation,  // 0도 회전
        m_Rotations[p1Index].orientation,  // 90도 회전
        scaleFactor                         // 0.5
    );
    // 결과: 45도 회전 (0도와 90도의 중간)
    
    return glm::toMat4(finalRotation);
}
```

    // 모델 그리기
    model_->Draw(shader);
}

## 4. 셰이더 코드 상세 분석

### 📝 Vertex Shader 전체 코드

```glsl
#version 330 core

// 입력 데이터
layout (location = 0) in vec3 aPos;        // 정점 위치
layout (location = 1) in vec3 aNormal;      // 법선 벡터
layout (location = 2) in vec2 aTexCoords;   // 텍스처 좌표
layout (location = 5) in ivec4 aBoneIDs;     // 뼈대 ID (4개)
layout (location = 6) in vec4 aWeights;      // 뼈대 가중치 (4개)

// 출력 데이터
out VS_OUT {
    vec3 FragPos;
    vec3 Normal;
    vec2 TexCoords;
    vec4 FragPosLightSpace;
} vs_out;

// Uniform 변수 (CPU에서 전달)
uniform mat4 model;                         // 모델 변환 행렬
uniform mat4 view;                          // 뷰 변환 행렬
uniform mat4 projection;                    // 투영 행렬
uniform mat4 lightSpaceMatrix;              // 그림자용 행렬
uniform mat4 finalBonesMatrices[100];       // 뼈대 변환 행렬 100개

// 뼈대 변환 행렬 계산 함수
mat4 getBoneTransform()
{
    // 1. 가중치 합계 확인
    float wSum = aWeights[0] + aWeights[1] + aWeights[2] + aWeights[3];
    if (wSum <= 0.0001)
        return mat4(1.0);  // 뼈대 영향 없음 → 단위 행렬 (변환 없음)
    
    // 2. 각 뼈대의 변환 행렬을 가중치로 곱해서 합산
    mat4 boneTransform = mat4(0.0);
    boneTransform += finalBonesMatrices[aBoneIDs[0]] * aWeights[0];
    boneTransform += finalBonesMatrices[aBoneIDs[1]] * aWeights[1];
    boneTransform += finalBonesMatrices[aBoneIDs[2]] * aWeights[2];
    boneTransform += finalBonesMatrices[aBoneIDs[3]] * aWeights[3];
    
    return boneTransform;
}

void main()
{
    // 1. 뼈대 변환 행렬 계산
    mat4 boneTransform = getBoneTransform();
    
    // 2. 정점 위치 변환
    // 원래 위치 → 뼈대 변환 적용 → 로컬 공간 위치
    vec4 localPos = boneTransform * vec4(aPos, 1.0);
    
    // 3. 법선 벡터도 변환 (회전만 적용, 이동/크기는 제외)
    vec3 localNormal = mat3(boneTransform) * aNormal;
    
    // 4. 월드 공간으로 변환
    vec4 worldPos = model * localPos;
    
    // 5. 출력 데이터 설정
    vs_out.FragPos = worldPos.xyz;
    vs_out.Normal = mat3(transpose(inverse(model))) * localNormal;
    vs_out.TexCoords = aTexCoords;
    vs_out.FragPosLightSpace = lightSpaceMatrix * worldPos;
    
    // 6. 최종 화면 좌표 계산
    gl_Position = projection * view * worldPos;
}
```

### 🔍 getBoneTransform() 함수 상세 분석

이 함수가 **스켈레탈 애니메이션의 핵심**입니다!

#### 예시: 팔꿈치 정점

```
입력 데이터:
aBoneIDs = [5, 6, -1, -1]  // UpperArm=5, LowerArm=6
aWeights = [0.6, 0.4, 0.0, 0.0]

finalBonesMatrices[5] = UpperArm의 변환 행렬 (예: 30도 회전)
finalBonesMatrices[6] = LowerArm의 변환 행렬 (예: 0도 회전)
```

**계산 과정:**

```glsl
// 1단계: 가중치 합계 확인
wSum = 0.6 + 0.4 + 0.0 + 0.0 = 1.0  // 정상

// 2단계: 각 뼈대 변환 행렬에 가중치 곱하기
mat4 boneTransform = mat4(0.0);  // 초기화

// UpperArm (ID=5)의 영향: 60%
boneTransform += finalBonesMatrices[5] * 0.6;
// → UpperArm이 30도 회전했다면, 60%만큼 적용

// LowerArm (ID=6)의 영향: 40%
boneTransform += finalBonesMatrices[6] * 0.4;
// → LowerArm은 그대로라면, 40%만큼 적용

// 최종 결과:
// boneTransform = (UpperArm 변환 × 0.6) + (LowerArm 변환 × 0.4)
```

**⚠️ 주의: 실제로는 행렬을 더하는 게 아니라...**

위 코드는 **의사코드**입니다. 실제로는 다음과 같이 계산합니다:

```glsl
// 실제 계산 방식 (더 정확한 버전)
vec4 pos1 = finalBonesMatrices[aBoneIDs[0]] * vec4(aPos, 1.0);
vec4 pos2 = finalBonesMatrices[aBoneIDs[1]] * vec4(aPos, 1.0);
vec4 pos3 = finalBonesMatrices[aBoneIDs[2]] * vec4(aPos, 1.0);
vec4 pos4 = finalBonesMatrices[aBoneIDs[3]] * vec4(aPos, 1.0);

vec4 finalPos = pos1 * aWeights[0] + 
                pos2 * aWeights[1] + 
                pos3 * aWeights[2] + 
                pos4 * aWeights[3];
```

하지만 현재 코드는 **행렬을 가중 평균**하는 방식으로도 작동합니다 (수학적으로 동일한 결과).

### 🎯 main() 함수 단계별 설명

```glsl
void main()
{
    // === 1단계: 뼈대 변환 행렬 계산 ===
    mat4 boneTransform = getBoneTransform();
    // 예: 팔꿈치 정점 → UpperArm 60% + LowerArm 40%의 변환 행렬
    
    // === 2단계: 정점 위치 변환 ===
    vec4 localPos = boneTransform * vec4(aPos, 1.0);
    // 원래 위치 (예: 0, 1, 0) → 뼈대 변환 적용
    // → 팔이 올라갔다면 정점도 올라감
    
    // === 3단계: 법선 벡터 변환 ===
    vec3 localNormal = mat3(boneTransform) * aNormal;
    // 법선도 뼈대 변환에 따라 회전해야 조명이 올바름
    // mat3()은 행렬에서 회전 부분만 추출 (이동/크기 제외)
    
    // === 4단계: 월드 공간 변환 ===
    vec4 worldPos = model * localPos;
    // 로컬 공간 → 월드 공간
    // model 행렬: 캐릭터의 위치, 회전, 크기
    
    // === 5단계: 출력 데이터 설정 ===
    vs_out.FragPos = worldPos.xyz;  // Fragment Shader로 전달
    vs_out.Normal = mat3(transpose(inverse(model))) * localNormal;
    // 법선을 월드 공간으로 변환 (조명 계산용)
    
    // === 6단계: 화면 좌표 계산 ===
    gl_Position = projection * view * worldPos;
    // 월드 공간 → 카메라 공간 → 화면 좌표
    // projection: 원근 투영
    // view: 카메라 변환
}
```

### 📊 전체 변환 파이프라인

```
원래 정점 위치 (aPos)
    │
    ▼
[뼈대 변환 적용]
boneTransform × aPos
    │
    ▼
로컬 공간 위치 (localPos)
    │
    ▼
[모델 변환 적용]
model × localPos
    │
    ▼
월드 공간 위치 (worldPos)
    │
    ▼
[뷰 변환 적용]
view × worldPos
    │
    ▼
카메라 공간 위치
    │
    ▼
[투영 변환 적용]
projection × (view × worldPos)
    │
    ▼
화면 좌표 (gl_Position)
```

## 🎓 요약

### 스켈레탈 애니메이션의 핵심 3단계

1. **데이터 준비**
   - 모델 로드: 정점에 뼈대 ID와 가중치 저장
   - 애니메이션 로드: 각 뼈대의 키프레임 데이터 저장

2. **CPU에서 계산**
   - 매 프레임 시간 업데이트
   - 키프레임 보간으로 각 뼈대의 변환 행렬 계산
   - 부모→자식 순서로 글로벌 변환 계산
   - 최종 변환 행렬 100개 생성

3. **GPU에서 적용**
   - 각 정점마다 뼈대 가중치로 변환 행렬 계산
   - 정점 위치 변환
   - 화면에 그리기

### 핵심 공식

```
최종 정점 위치 = Σ (뼈대_i 변환 행렬 × 가중치_i) × 원래 위치
```

예: 팔꿈치 정점
```
최종 위치 = (UpperArm 변환 × 0.6 + LowerArm 변환 × 0.4) × 원래 위치
```
